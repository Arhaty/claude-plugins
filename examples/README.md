# Examples

A filled-in spec and the canon file it produced, from a fictional web app with a login form.

- [docs/specs/archive/012-rate-limit-sign-in.md](docs/specs/archive/012-rate-limit-sign-in.md)
  is the argument for one change, as `/canon:define` wrote it and `/canon:staging` archived it.
- [docs/canon/auth.md](docs/canon/auth.md) is how sign-in works today, after `/canon:canon` wrote
  what that spec settled.

Read them side by side: the spec says why and is frozen once shipped; the canon file states the
rule and keeps changing as the code does.
